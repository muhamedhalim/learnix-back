## 1. How the frontend consumes API addresses (code-verified)

`learnix-front` has **one** API address variable. There is no server-only equivalent and no separate server-side API variable.

| Consumer                                                              | File                                                     | How it reads the variable                                                                                                                                                                                           | Runs where                            |
| --------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| Axios client (all authenticated and public API calls, CSRF bootstrap) | `app/[locale]/hooks/axios.config.ts:10`                  | `process.env.NEXT_PUBLIC_API_URL`, inlined at **build time**; throws at import when unset; `normalizeApiBaseUrl` guarantees exactly one `/api/v1` suffix (bare origin or versioned base both work; V-TEST 28 tests) | Browser and server components         |
| Certificate verify page (PDF link)                                    | `app/[locale]/(public)/verify/[code]/page.tsx:13,91,103` | Imports `API_URL` from the axios module                                                                                                                                                                             | Server render, link opened in browser |
| Marketplace sitemap                                                   | `app/[locale]/(public)/marketplace/sitemap.ts:36`        | `process.env["NEXT_PUBLIC_API_URL"] ?? "http://localhost:3001"` (bracket access, **not inlined**: read at server runtime) then `normalizeApiBaseUrl` (V-TEST 5 tests)                                               | Vercel server / build                 |
| Seed script                                                           | `scripts/seed-admin.mjs`                                 | Local tooling only                                                                                                                                                                                                  | Developer machine                     |
| CI build                                                              | `.github/workflows/ci.yml`                               | `vars.NEXT_PUBLIC_API_URL_CI` (GitHub), fallback to the retired Railway URL                                                                                                                                         | GitHub Actions, not Vercel            |

Consequences:

1. Changing `NEXT_PUBLIC_API_URL` needs a **new Vercel build**. The sitemap reads the variable at runtime while client code is baked in, so a variable change without a redeploy can make them disagree.
2. There is no hidden second API variable to forget. Every API URL in the product follows this one value.
3. The browser calls the API host directly (cross-origin, same-site); there is no Next.js rewrite/proxy to the API (`next.config.ts` has no `rewrites`, no `headers()`, no CSP).

## 6. Safe validation commands (read-only)

```bash
# What does the public API host answer, and from which edge?
curl -sS -I https://api.learnix.school/api/v1/health/readiness

# Preflight from the real frontend origin (expect ACAO = https://learnix.school and Allow-Credentials: true)
curl -sS -i -X OPTIONS https://api.learnix.school/api/v1/auth/csrf-token \
  -H 'Origin: https://learnix.school' -H 'Access-Control-Request-Method: GET'

# A foreign and a Vercel-preview origin must receive NO Access-Control-Allow-Origin
curl -sS -i -X OPTIONS https://api.learnix.school/api/v1/auth/csrf-token \
  -H 'Origin: https://example.vercel.app' -H 'Access-Control-Request-Method: GET'

# Full acceptance run (read-only), before DNS is changed: pin to the distribution
node learnix-infra/scripts/staging-acceptance.mjs https://api.learnix.school --frontend https://learnix.school --pin <cloudfront_domain_name>

# DNS resolves the API host to CloudFront on the public resolvers
node learnix-infra/scripts/cutover-verify.mjs api.learnix.school <cloudfront_domain_name>
```

Never run `cutover-verify.mjs` against the apex expecting CloudFront: the apex intentionally stays on Vercel.

## 7. Rules for handling values

- Write secrets only to Vercel (as Sensitive/encrypted variables), Secrets Manager or your password manager. Never paste them into this file, tickets or chat.
- Only `NEXT_PUBLIC_*` values may be non-secret in the browser bundle. `SENTRY_AUTH_TOKEN` is build-time only and must never be `NEXT_PUBLIC_`.
- Before changing a Vercel variable, copy its current value (or note that it is encrypted) so the Production change in cutover Step 8 is reversible.
- Production and staging must use distinct Paymob integration ids, Sentry projects, and Firebase projects; the backend isolation guard enforces several of these at boot.
